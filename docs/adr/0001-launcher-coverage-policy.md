# launcher 커버리지 게이트 제외

- 상태: 확정
- 일자: 2026-10-21

## 배경

launcher는 실행 진입점과 모듈 조립을 담당한다. `main()` 실행률을 채우기보다 역할 제한과 실제 기동·연결을 검증한다.

## 결정

- launcher는 모듈별 커버리지 게이트에서 제외하고, 나머지 모듈의 기본 80% 게이트는 유지한다.
- launcher 운영 코드는 진입점과 승인된 설정 클래스로 한정한다. 컨트롤러·서비스·저장소 구현 등 비즈니스 로직은 두지 않는다.
- 운영 클래스 추가 시 역할과 제외 정책을 재검토한다. 허용 클래스 범위는 ArchUnit으로 검증하고, 메서드 내부의 역할 준수는 코드 리뷰로 보완한다.
- launcher의 기동·HTTP → 유스케이스 → 저장 통합 테스트를 유지한다. 통합 테스트가 launcher에 위치해도 운영 코드의 게이트 제외 정책은 동일하다.
- 모듈별 보고서에 다른 모듈에서 실행한 통합 테스트 결과가 자동 합산되지는 않는다. 전체 커버리지 집계는 필요할 때 보고용으로 추가하고, 별도 게이트 도입은 이후 결정한다.

## 후속 작업

launcher 운영 클래스 허용 범위를 제한하는 ArchUnit 규칙은 아직 구현하지 않았다. 체크리스트의 별도 P0 항목으로 추적한다.
